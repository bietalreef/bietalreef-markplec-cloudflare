# نموذج عمل السوق الجديد

## نطاق هذه الدفعة

نموذج جديد كليًا للشاشات وتجربة الاستخدام. المصدر: توجيهات المالك في جلسة 15 أكتوبر 2026. ليس تقريرًا إحصائيًا، ولا يتضمن تحليلًا لسجلات العملاء. لا يدّعي وجود مزودين أو منتجات أو مشتريات. جميع الحقول في شاشة التفاصيل قوالب معنونة وليست بيانات فعلية.

## ما الذي يفعله الزائر؟

الرئيسية ← القسم أو البحث ← اختيار النوع والمدينة ← النتائج ← تفاصيل العنصر ← النشاط المرتبط. عند عدم توفر محتوى، توضح الشاشة الحالة وتقترح العودة للأقسام. معاينة تصميم البطاقة والمتجر منفصلة بوضوح عن النتائج.

## ما الذي يفعله صاحب النشاط؟

يدخل إلى التطبيق الرسمي، ويربط بياناته ومساحة العمل حسب النظام الحالي. ينشئ أصل العنصر ويحفظه. يحكم نظام الاشتراكات الحالي صلاحية الأداة وحدود استخدامها. لا تثبت أرقام الباقات داخل واجهة السوق.

ظهور العنصر في الملف داخل التطبيق لا يساوي اعتماده في فهرس السوق. للسوق والمنصة قرار قناة مستقل. لوحة الإدارة تدير الحساب والاعتماد والصلاحيات وسجل القرارات؛ لا تنشئ عناصر نيابة عن الحساب.

## عقد الربط القادم — غير منفذ هنا

- Supabase هو مصدر الحقيقة. إعادة استخدام المعرفات والجداول وRPCs الحالية بعد فحصها؛ دون بناء مخطط موازٍ.
- أصل بطاقة واحد: معرف، معرف النشاط، النوع، العناوين، الوصف، الصور، الحقول المختصة، والإصدار. هذه دلالات مطلوبة وليست أسماء جداول أو عقود RPC مخترعة.
- عرض عام يقتصر على الحقول المسموح بنشرها والعناصر المؤهلة لقناة السوق؛ لا كشف مسودات أو بريد خاص أو مستندات التوثيق.
- الأصل الخاص للصور في مساحة العمل وفق صلاحيات صاحبها. العرض العام يحتاج مشتقًا عامًا معتمدًا عبر طبقة الوسائط الحالية، لا جعل مجلد Drive بالكامل عامًا ولا تضمين رموز OAuth في روابط الصور.
- تحديث سجل العنصر يحدّث العرض من الأصل نفسه. تستخدم آلية الأحداث الحالية لإبطال الكاش وإعادة جلب العنصر، مع معالجة فشل المزامنة؛ لا إنشاء نسخ مستقلة لكل قناة.
- تحفظ الأخطاء وحالة الرفع وإعادة المحاولة. لا تصبح البطاقة جاهزة للنشر قبل اكتمال الوسائط المطلوبة.
- أزرار التواصل والطلبات تربط بالعقود الموجودة لاحقًا؛ في هذا النموذج توضح المعاينة أنها لا ترسل شيئًا.

## الأسماء والانتقال

اسم المستودع الفعلي `bietalreef-markplec-cloudflare` مطابق لطلب المالك، والعنوان البرمجي المقروء `bietalreef-marketplace`. الأسماء الأخرى موثقة في repository-map.json بعد فحص GitHub وCloudflare. مشروع السوق الإنتاجي الحالي `appbietalreef` ما زال مربوطًا بـFigmawebapp. لا يحول هذا النموذج الدومين الإنتاجي إلى المستودع الجديد.

قبل أي انتقال إنتاجي: اعتماد الشاشات، ربط البيانات العامة، اختبار صلاحيات واشتراكات وقنوات، جرد الروابط المفهرسة ومساراتها، مطابقة canonical/hreflang وبيانات الصفحات وخرائط الموقع، فحص الصور والأداء والهاتف، ثم خطة تحويل ورجوع. النموذج الحالي يستخدم hash navigation للمراجعة فقط وليس بديلًا لمسارات SEO الإنتاجية.

## معايير القبول لهذه المعاينة

شاشات قابلة للتصفح، قائمة يمينية قابلة للإغلاق بلوحة المفاتيح، بحث وتصفية ينعكسان على الواجهة، لا بيانات مصطنعة، لا مفاتيح أو ملفات قديمة، لا اتصال ببيانات الإنتاج، ومنع الفهرسة في HTML وHTTP وrobots.txt. لا تعتبر اختبارات المعاينة إثباتًا لجاهزية التجارة أو الدفع أو المزامنة.
